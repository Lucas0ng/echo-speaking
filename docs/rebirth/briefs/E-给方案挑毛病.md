# 任务 E：给方案挑毛病

读 `docs/rebirth/PLAN.md`（方案初稿），需要依据时再读 `docs/rebirth/reports/` 里的调研报告。你的任务是找出这份方案里会让它失败的地方，不是润色，也不用夸。

## 要回答的问题

1. **会不会重蹈覆辙。** 用户放弃旧版的原因是"每次照本宣科地读，读完得过且过，看不到进步"。新方案的一节 25 分钟里，哪一段最可能又变成走过场？具体会怎么变？怎么改能防住？
2. **3000 节的说法站不站得住。** 方案说 3000 节（1250 小时）口语到 C1 有把握。核对 `reports/A-*.md` 里的数字和原始来源，这个说法是偏乐观、偏保守，还是根本没法这么算？
3. **五个阶段的节数分配**（200 / 400 / 700 / 900 / 800）有没有明显不合理的地方。哪个阶段最可能卡住很久？
4. **一节课的五段**（回忆 4、声音 4、新句 7、用 7、快 3 分钟）：时间够不够做完写的那些事？哪一段应该砍掉或合并？有没有漏掉的关键环节？
5. **内容由大模型批量生成**的风险：句子不自然、难度乱跳、前后不搭建。怎样抽检才够？有没有更稳的内容来源？
6. **做完 100 节时用户最可能在抱怨什么。** 参考 `reports/B-*.md` 里各家软件的用户抱怨。
7. **方案漏掉了什么。** 例如听力输入太少、没有真人对话、长期没有新鲜感，等等。按严重程度排序，只列你认为真的会出事的。

每一条都要给：问题是什么、为什么会出事（有依据的给来源链接）、建议怎么改。没问题的地方直接写"没问题"，不要凑数。

## 交回方式

报告由你自己写进文件，边查边存，不要等全部查完，也不要交给用户代存。

1. 开工第一步：新建 `docs/rebirth/reports/E-你的名字.md`（例如 `E-muse.md`，路径相对于用户给你的仓库文件夹）。第一行写：评审者、日期；第二行写 `状态：进行中`。
2. 每答完上面的一个问题，就把这一节写进文件并存盘。
3. 全部答完后，把"最该改的三处"补到文件最前面，第二行改成 `状态：完成`。
4. 只写这一个文件，不要改方案本身。用简体中文，控制在 2000 字以内。
