# 任务 D：现有代码盘点

适合能直接读这个仓库的 AI（例如 Cursor）。只读代码、写报告，**不要改任何代码**。

## 背景

这个仓库是一个 Mac 上的英语口语练习软件「回声」。后端是 `app.py`（FastAPI，本机 Whisper 识别、调大模型、存录音和状态），前端是 `static/` 下的原生 JS（没有框架，没有构建步骤）。`windows/` 是整份独立副本，这次不用看。

现在的课程是按 IELTSCast 播客的发布顺序排的（`app.py` 的 `build_lessons()`），每天三步：跟读、语块造句、开口说。我们准备大改，代号 Rebirth：换成一条从发音和最简单的句子开始、分阶段往上爬的课程路线，每节 25 分钟，按节数倒计时。现有的录音、识别、点评、复习能力要尽量复用。

## 要回答的问题

1. **功能清单**：每个功能在哪个文件、哪几个函数里实现（跟读、语调对比、开口说点评、4/3/2、自言自语、语块本和间隔复习、错误本、发音体检和最小对立对、AI 对话、进步页、我的素材、点词词典）。给文件名和行号。
2. **状态结构**：前端的 `S` 对象（`static/app.js` 第 75 行附近）每个字段存什么、谁读谁写；后端 `/api/state` 怎么存盘和备份；录音的元数据有哪些字段。
3. **和课程顺序绑死的地方**：哪些代码假设了"一课 = 一集 IELTSCast 音频"（例如 `S.prefs.cur`、`S.lessons[n]`、`renderToday`、`buildStep1/2/3`、`goLesson`、对话里的 `CHAT.lesson`）。列出每一处，说明如果课程换成"自定义的课程单元"（一个单元 = 若干练习项，不一定有音频），这一处要怎么改。
4. **可以原样复用的部件**：哪些函数和接口与课程内容无关，新课程可以直接调用（例如 `Rec`、`stt`、`aiText`、`schedule`、`pitchSvg`、`timedRec`、`/api/stt`、`/api/pitch`、`/api/recordings`）。给每个部件写一句它的输入和输出。
5. **新课程层的接入点**：如果新增一个 `static/course.js` 和一份课程数据文件（JSON），最少要动现有的哪几个地方才能让「今天」页改成跑新课程，同时旧的「我的素材」「语块本」「错误本」等页照常工作。
6. **风险**：`static/app.js` 有 2500 多行，哪些部分互相缠得最紧、改的时候最容易碰坏；现有用户数据（`data/` 里的状态和录音）在换课程后哪些还有意义、哪些需要迁移。

## 交回方式

报告由你自己写进文件，边查边存，不要等全部查完，也不要交给用户代存。

1. 开工第一步：新建 `docs/rebirth/reports/D-你的名字.md`（例如 `D-cursor.md`，路径相对于用户给你的仓库文件夹）。第一行写：调研者、日期；第二行写 `状态：进行中`。
2. 每答完上面的一个问题，就把这一节写进文件并存盘，再去查下一个。中途断了，已经查到的也留得下来。
3. 全部答完后，把结论小结补到文件最前面，第二行改成 `状态：完成`。
4. 只写这一个文件。你确实没有写本机文件的能力时，在回复的第一句话说明，再输出全文。
