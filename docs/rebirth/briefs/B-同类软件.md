# 任务 B：同类软件

至少覆盖这些（每个查官网介绍 + 至少一处真实用户评价，例如 Reddit、App Store 评论、知乎、小红书、Hacker News）：
- AI 口语类：Speak、ELSA Speak、Praktika、Loora、BoldVoice、Duolingo（含 Max 的 Roleplay / Video Call）、英语流利说、多邻国之外的国内产品（如 Hi Echo、Call Annie 同类、豆包口语练习）
- 体系课程类：Pimsleur、Glossika、Rosetta Stone、Babbel、Busuu、Michel Thomas、Assimil
- 输入类：Dreaming Spanish（它的“小时数路线图”和进度页是怎么设计的）、LingQ、Refold（它的分阶段路线图）、Language Reactor
- 记忆类：Anki、不背单词、扇贝、墨墨
- 真人类：italki、Cambly、Preply（只看它们怎么安排课程结构和进度）

每个产品回答：
1. 一节课的核心循环是什么（用户具体做什么动作，开口占多少）。
2. 课程是怎么排的：从零到高级的路线、分级依据（CEFR？自定级别？）、有没有分级测试。
3. 进度怎么让人看得见（小时数、等级、can-do、连续天数、分数……），用户觉得哪种真实、哪种是假进度。
4. 用户最常见的抱怨和流失原因。
5. 对一个“每天 25 分钟、单人自用、目标是真的会说”的自制软件，最值得照搬的一个设计，和最该避开的一个坑。

最后给一个总表（产品 / 核心动作 / 进度呈现 / 值得搬 / 要避开），以及你认为最值得借鉴的 5 个设计，按价值排序。
特别关注：Pimsleur 的“分级间隔回忆 + 预期原则（先问再答）”、Glossika 的整句大量重复、Speak 的“先学句子再开口再自由对话”三段式、Dreaming Spanish 的小时计数和分级路线图——这几个要查细。

## 通用要求

- 你是调研员，只做联网调研和写报告，不要改任何代码。
- 必须真的联网查，把页面内容读过再写。每条结论后面跟你实际打开过的来源链接。打不开或没查到的，明确写“未查到”，不要凭印象编数字、编链接。
- 把“来源原文说的”和“你的推断”分开写。
- 报告用简体中文、Markdown，先给结论再给依据，控制在 2500 字以内，不要套话。

## 学习者画像

母语中文的成年人，阅读还行、听力中等、口语弱；每天只练 25 分钟；长期目标是把英语练到“第二母语”的程度（想说什么张口就来，不经过中文翻译）。自己做了一个 Mac 上的口语练习软件，用本机 Whisper 做语音识别、大模型做点评和对话。

## 交回方式

报告由你自己写进文件，边查边存，不要等全部查完，也不要交给用户代存。

1. 开工第一步：新建 `docs/rebirth/reports/B-你的名字.md`（例如 `B-gemini.md`，路径相对于用户给你的仓库文件夹）。第一行写：调研者、日期、用了什么联网手段；第二行写 `状态：进行中`。
2. 每答完上面的一个问题，就把这一节写进文件并存盘，再去查下一个。中途断了，已经查到的也留得下来。
3. 全部答完后，把结论小结补到文件最前面，第二行改成 `状态：完成`。
4. 只写这一个文件。你确实没有写本机文件的能力时，在回复的第一句话说明，再输出全文。
